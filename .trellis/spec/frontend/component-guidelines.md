# Component Guidelines

> How UI "components" are built in this project (VS Code webviews, not React).

---

## Overview

There is **no component framework**. UI consists of two VS Code webviews whose
HTML/CSS/JS is generated by template-literal functions in
`src/formula/panel.js`:

- `getPanelHtml(cspSource)` — sidebar controls (counts, buttons, checkboxes)
- `getBrowserHtml(cspSource)` — full formula/theorem browser tab

Inside the webview, DOM is built imperatively (`document.createElement`,
`innerHTML` for static fragments), state lives in top-level `let` variables,
and a central `render()` re-creates the list DOM on every state change.

---

## Webview Structure

Real example — every webview HTML follows this shape (see `getPanelHtml`):

```js
function getPanelHtml(cspSource) {
    const nonce = getNonce();
    return /* html */ `<!DOCTYPE html>
<html>...<meta http-equiv="Content-Security-Policy"
    content="default-src 'none'; style-src ${cspSource} 'unsafe-inline';
             script-src 'nonce-${nonce}';">...
<script nonce="${nonce}"> ... </script>`;
}
```

Rules:

- **CSP nonce is mandatory** — every `<script>` carries `nonce="${nonce}"`
  from `getNonce()`; never relax CSP to allow inline scripts without nonce.
- **Styling uses VS Code theme tokens** (`var(--vscode-foreground)`,
  `var(--vscode-button-background)`, …), never hard-coded dark/light colors
  (exception: the formula SVG viewport deliberately uses a fixed white
  background because dvisvgm output is black-on-transparent).
- **User-facing webview strings are in English**; extension-host comments and
  docstrings are in Chinese.

## Host ↔ Webview Communication

- Webview → host: `vscode.postMessage({ type: '...', ... })`.
- Host → webview: `webview.postMessage(...)`; when the browser tab is closed,
  `FormulaBrowser.sendMessage()` queues messages and **keeps only the latest
  message per `type`** to avoid replaying stale state on reopen.
- The webview sends `{ type: 'ready' }` on load; the host then replays
  pending data (formulas, recent/pinned labels, toggle states).
- Message handling on the host side: small `switch (message.type)` in the
  provider, shared actions in `handlePanelMessage()`.

## Composition Pattern

- One provider class per view (`FormulaPanelProvider`, `FormulaBrowser`),
  constructed with `context`, exposing `_onX` callback fields that
  `extension.js` assigns (e.g. `_onToggleShowRecent`).
- Interactive cards are created by factory functions
  (`createFormulaElement`, `createTheoremElement`) that attach their own
  event listeners; grouped lists use `makeCollapsible(title, items, level, createEl)`.

## Accessibility

- Icon-only buttons get a `title` tooltip (e.g. pin button: "Pin formula").
- Collapse/expand arrows reuse the VS Code chevron SVG with an
  `expanded` CSS rotation class.

## Common Mistakes

- **Template-literal escaping**: the webview script lives inside a JS template
  literal, so a literal backslash in webview code needs `\\\\` in source
  (e.g. inserting `\ref{...}` is written `'\\\\ref{'`). Verify via a node
  smoke test on `getBrowserHtml()` output when adding TeX strings.
- Forgetting `stopPropagation()` on inner buttons (pin) — the card's own
  click handler would also fire (copies the label).
